# TrainFrame

Turns plain-text `.frame` files into interactive walkthroughs (ECEN 305 HW3-style formula cross-refs, ELEN 304 HW3-style slider plots). Part of the study apps at https://braxtonstryker.github.io/ (with QuizQrusher in `../Quiz_Qrusher/`, InfoBase in `../Class_Base/`, CwikCard in `../CwikCard/` and RunDown in `../RunDown/`). To be hosted on GitHub Pages at `/TrainFrame/` (repo `BraxtonStryker/TrainFrame`). **v0.1.0** (2026-11-02): the working shell, which is step 2 of [PLAN.md](PLAN.md).

## Layout
- `index.html`: the whole app. `sw.js`, `manifest.webmanifest`, `icons/` (`icon.svg` and `icon-maskable.svg` are the sources of the PNGs, rendered with headless Chrome): the installable offline app. `vendor/katex.min.js` is the same KaTeX build RunDown and InfoBase use, for the renderer.
- `docs/LANGUAGE.md`: the frame language spec (v0.2). `PLAN.md`: the 12-step plan, the layout and the settled decisions. Change the spec before the code, and log language changes in its version history.
- `examples/demo.frame`: invented problems, shipped and precached. `examples-private/` (gitignored, as are the two original walkthrough HTML files in the root): the user's real homework converted, used as test material. Never commit them; the repo is public.
- `tools/sw_version.py`: `python -I tools/sw_version.py --sync` after changing any precached file, or the service worker won't ship the change.
- `tools/harness.py`: headless-Chrome checks over the DevTools protocol (stdlib only). Rerun after any change and extend it. It accepts `confirm()` dialogs by itself; `click_el` scrolls only when the element is off screen, as a person would.

## Conventions (match RunDown, QuizQrusher and CwikCard)
- Single-file HTML, inline CSS and JS, vanilla JS in an IIFE, `var` and `function` style, no frameworks, no build step, nothing from CDNs (Atkinson Hyperlegible is inlined from RunDown).
- Every color is a CSS custom property on `:root`, with dark values for "Match system" and `data-theme="dark"`. Font sizes are `calc(Npx * var(--fs))`. Teal is TrainFrame's color: the default accent (`#0F766E` / `#2DD4BF`, the Teal preset), the app switcher entry (`--app-tf`) and the icon (gradient `#14A396` to `#0B5F59`, details `#0F766E`).
- American spelling. Every localStorage, IndexedDB and cache name starts with `trainFrame` (`trainFrame:settings`, `trainFrame:tabs`, `trainFrame:scroll`, `trainFrame:notesOpen`, `trainFrame:calcOpen`, `trainFrame:calcPos`, IndexedDB `trainFrame:app`, caches `trainFrame-<version>`): all of the user's GitHub Pages apps share one origin.
- Copied from RunDown and kept in step by hand: the appearance block in `<head>`, the storage backends, Settings rows, the toast, the app switcher and the service worker. The app switcher lists QuizQrusher, InfoBase, CwikCard, RunDown, TrainFrame, then Home. The other four apps don't list TrainFrame yet; that's the Ship step, and it needs the user's OK for each repo.
- Log each release in Help > What's new and bump `APP_VERSION`.

## How it works (0.1)
- **Data:** IndexedDB `trainFrame:app` (version 2) with stores `files` (`{id: the @frame id, text, fileName, addedAt, updatedAt, cls, folder, title}`; `cls`, `folder` and `title` are set in the app and `null` means the file's own), `notes` (`{id, text, updatedAt}`, one per file), `places` (`{id: cls + "" + path, cls, path}`: classes and folders made in the app, so empty ones still show) and `classes` (`{id: name, archived, from: [old names]}`). Falls back to localStorage, then memory. Backups are `trainframe-backup` JSON (the newer copy wins on import).
- **Renamed classes:** `ALIAS` maps every old name in `classes[].from` to the new one, and `ownCls()` applies it, so files whose `class:` line has an old name keep landing in the renamed class. A rename also rewrites `files[].cls` overrides, `places` and the tabs.
- **`readFrame(text)`** is a stand-in for the parser (plan step 3). It reads the `@frame` header (id, title, class, folder, subtitle, facts, intro) and the `@problem` / `@formula` / `@definition` header lines. IDs may be in braces (`@formula {F1} Title`). A file whose first block isn't `@frame <id>` is refused.
- **Screens and tabs:** `SCREEN` is `home` (the Library: every class, archived ones in a fold, then Add files), `class`, `help` or `settings`. `TABS` (localStorage `trainFrame:tabs`) holds the open class tabs (shown next to Library in the top bar), the current class, and per class `{section, path, files, file}`: the section and folder it was on, its open file tabs and the one showing. Every change of view goes through `nav(change)`, which saves the notes, records `scrollY` for the view being left (`SCROLL`, keyed `f:<id>` for files, kept in `trainFrame:scroll`), applies the change, tidies the tabs, renders and restores the new view's scroll spot.
- **Sticky bars:** the top bar and a class's header (file tabs and section tabs, `#chead`) are sticky, so switching tabs never scrolls the page first; that is what makes the remembered spots meaningful. `setStick()` writes their heights to `--bar` and `--stick`, which the rail and the scroll margins use.
- **An open file:** the rail lists Formulas and the problems; `spy()` highlights the problem whose source line has scrolled under the bars. Until the renderer lands, `#frameMain` shows where the file is filed, the title block and the source with line ids `L<n>`.
- **Safety:** a frame file is never run as code. Everything from a file goes through `esc()`, and the expression engine (step 3) must be a parser, never `eval` or `Function`.
