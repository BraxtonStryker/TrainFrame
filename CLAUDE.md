# TrainFrame

Turns plain-text `.frame` files into interactive walkthroughs (ECEN 305 HW3-style formula cross-refs, ELEN 304 HW3-style slider plots). Part of the study apps at https://braxtonstryker.github.io/ (with QuizQrusher in `../Quiz_Qrusher/`, InfoBase in `../Class_Base/`, CwikCard in `../CwikCard/` and RunDown in `../RunDown/`). To be hosted on GitHub Pages at `/TrainFrame/` (repo `BraxtonStryker/TrainFrame`). **v0.6.2** (2026-11-16): fixes the stray "displaystyle" in the calculator's math. v0.6.1 (2026-11-15): the Calc tab typesets its math and has a phone layout. v0.6.0 (2026-11-15): the calculator (plan step 7), the hub (step 6: Formula sheet, Search, standalone HTML) and the renderer fine-tuning. v0.5.0 (2026-11-02): live visuals (plan step 5). v0.4.0: Copy AI prompt (`prompts/generator.md` plus `docs/SYNTAX.md`, both precached), dismissable load-report items (`trainFrame:dismissed`), and the no-check warning behind Settings > Files (off by default). v0.3.0: the renderer, first pass (plan step 4). v0.2.0: the parser, checker and load report (step 3). v0.1.0 (2026-11-02): the working shell (step 2).

## Layout
- `index.html`: the whole app. `sw.js`, `manifest.webmanifest`, `icons/` (`icon.svg` and `icon-maskable.svg` are the sources of the PNGs, rendered with headless Chrome): the installable offline app. `vendor/katex.min.js` is the same KaTeX build RunDown and InfoBase use, for the renderer.
- `docs/LANGUAGE.md`: the frame language spec (v0.3). `docs/SYNTAX.md`: the lean version written for an AI; its example must load clean (the harness checks). `docs/TODO.md`: the working list, with sections for Sam and for Claude; follow its instructions. `PLAN.md`: the 12-step plan, the layout and the settled decisions. Change the spec before the code, and log language changes in its version history.
- `examples/demo.frame`: invented problems, shipped and precached. `examples-private/` (gitignored, as are the two original walkthrough HTML files in the root): the user's real homework converted, used as test material. Never commit them; the repo is public.
- `tools/sw_version.py`: `python -I tools/sw_version.py --sync` after changing any precached file, or the service worker won't ship the change.
- `tools/harness.py`: headless-Chrome checks over the DevTools protocol (stdlib only; 242 checks at 0.6.0). Rerun after any change and extend it. `--shots DIR` saves screenshots, including the phone ones. The local preview server keeps an old service worker: unregister it and delete the `trainFrame-` caches when the page looks stale. It accepts `confirm()` dialogs by itself; `click_el` scrolls only when the element is off screen, as a person would.

## Conventions (match RunDown, QuizQrusher and CwikCard)
- Single-file HTML, inline CSS and JS, vanilla JS in an IIFE, `var` and `function` style, no frameworks, no build step, nothing from CDNs (Atkinson Hyperlegible is inlined from RunDown).
- Every color is a CSS custom property on `:root`, with dark values for "Match system" and `data-theme="dark"`. Font sizes are `calc(Npx * var(--fs))`. Teal is TrainFrame's color: the default accent (`#0F766E` / `#2DD4BF`, the Teal preset), the app switcher entry (`--app-tf`) and the icon (gradient `#14A396` to `#0B5F59`, details `#0F766E`).
- American spelling. Every localStorage, IndexedDB and cache name starts with `trainFrame` (`trainFrame:settings`, `trainFrame:tabs`, `trainFrame:scroll`, `trainFrame:notesOpen`, `trainFrame:calcOpen`, `trainFrame:calcPos`, `trainFrame:calc`, `trainFrame:progress`, `trainFrame:dismissed`, `trainFrame:bundleSeen`, IndexedDB `trainFrame:app`, caches `trainFrame-<version>`): all of the user's GitHub Pages apps share one origin.
- Copied from RunDown and kept in step by hand: the appearance block in `<head>`, the storage backends, Settings rows, the toast, the app switcher and the service worker. The app switcher lists QuizQrusher, InfoBase, CwikCard, RunDown, TrainFrame, then Home. The other four apps don't list TrainFrame yet; that's the Ship step, and it needs the user's OK for each repo.
- Log each release in Help > What's new and bump `APP_VERSION`.

## How it works (0.1)
- **Data:** IndexedDB `trainFrame:app` (version 2) with stores `files` (`{id: the @frame id, text, fileName, addedAt, updatedAt, cls, folder, title}`; `cls`, `folder` and `title` are set in the app and `null` means the file's own), `notes` (`{id, text, updatedAt}`, one per file), `places` (`{id: cls + "" + path, cls, path}`: classes and folders made in the app, so empty ones still show) and `classes` (`{id: name, archived, from: [old names]}`). Falls back to localStorage, then memory. Backups are `trainframe-backup` JSON (the newer copy wins on import).
- **Renamed classes:** `ALIAS` maps every old name in `classes[].from` to the new one, and `ownCls()` applies it, so files whose `class:` line has an old name keep landing in the renamed class. A rename also rewrites `files[].cls` overrides, `places` and the tabs.
- **Expressions** (`parseExpr`, `evaluate`): TrainFrame's own tokenizer, recursive-descent parser and tree evaluator, never `eval` or `Function`. Values are numbers or `{re, im}`; `fix()` drops a negligible imaginary part. Lets are dynamically scoped (they see the variables where they're used, so a plot's let can use its sliders), with a depth guard against self-use. `integral()` is adaptive Simpson on 16 starting panels (fixed Simpson failed a square-wave check). Every name table is `Object.create(null)` (`dict()`), so names like `constructor` aren't found.
- **`parseFrame(text)`** turns a file into `{id, title, cls, folder, subtitle, kind, steps, facts, intro, problems, formulas, lines, errors, warnings, checks, blocks, items, lets}`, or `null` when the first block isn't `@frame` (the file is refused). Passes: lines into blocks; structure (IDs, problem membership, attachments: a visual or callout belongs to the block above it); visuals (`parseVisual`: `;` clauses, keywords per panel type, options, names each visual defines); text (math must close, `{{refs}}` outside math, `{= live values}` anywhere); refs; let bodies; `check:` lines (tolerance: half the last written decimal, else 1e-6 relative); warnings. `blocks`/`items` are the tree the renderer draws; `sections` lists the `@section` blocks for the rail and `math` every math span with its line. `texCheck(info)` runs those spans through KaTeX (`throwOnError`) the first time `issues()` is asked after KaTeX has loaded, and adds what fails to `info.errors` (kind `tex`).
- **Load report:** errors and warnings with line numbers on an open file (each line links to the source, which marks it), on its card and in the Add files report. `reportText(id)` is the **Copy report for AI** text.
- **Screens and tabs:** `SCREEN` is `home` (the Library: every class, archived ones in a fold, then Add files), `class`, `help` or `settings`. `TABS` (localStorage `trainFrame:tabs`) holds the open class tabs (shown next to Library in the top bar), the current class, `files` (every open file tab, from any class, in one strip under the top bar) and per class `{section, path, file}`: the section and folder it was on and the file showing. While a file shows, the section tabs are hidden. Every change of view goes through `nav(change)`, which saves the notes, records `scrollY` for the view being left (`SCROLL`, keyed `f:<id>` for files, kept in `trainFrame:scroll`), applies the change, tidies the tabs, renders and restores the new view's scroll spot.
- **Sticky bars:** the top bar, the file-tab strip (`#fstrip`) and a class's section tabs (`#chead`) are sticky, so switching tabs never scrolls the page first; that is what makes the remembered spots meaningful. `setStick()` writes their heights to `--bar`, `--strip` and `--stick`, which the rail and the scroll margins use.
- **Right-edge dock** (`#noteDock`, as in QuizQrusher): NOTES and FORMULAS (the file's formula bank, math through KaTeX loaded on demand) show on an open file; CALC opens the calculator window on every screen.
- **An open file:** the rail lists Formulas, then the problems and `@section`s in the file's order; `spy()` highlights the one that has scrolled under the bars (`curProblem`, `curLine`). In a `kind: notes` file a formula is drawn in the bank (id `FB<line>`) and where it's written (id `L<line>`).
- **KaTeX** loads as soon as there are files (`needKatex`). At startup an open file waits for it (`whenKatex`, 1.5 s at most) so the scroll spot is restored on the final layout, and `redrawFile()` keeps the block under the sticky bars where it was.
- **Renderer** (`renderDoc`, `problemHtml`, `md`, `inline`): draws `info.items` (formula bank first, with "Used in"; then problems, sections, checklists, top-level callouts and visuals). Each run of steps becomes a stepper (`steps: per part` closes one at every `@part`; `per problem` keeps one and puts each part's heading on the step after it); its units are steps, answers and explains, and `trainFrame:progress` keeps how many show (default 1) plus checklist ticks. Rendered blocks get ids `L<line>`; the source moved to the closed `#srcBox` with ids `S<line>`, and `goLine` uses the block when it's visible, else the source. Math is KaTeX MathML (`tex()`), re-drawn when KaTeX finishes loading. `{= }` live values in body text are worked out with the lets only (`liveNum`: up to 3 decimals, trailing zeros dropped).
- **Visuals** (`makeFig`, `figHtml`, `plotHtml`, `phasorHtml`, `tableHtml`, `calcInputs`/`calcOutputs`): each figure in `FIGS` (by line) keeps its variables and view. The parser keeps each visual line's main part in `it.rest` and its options in `it.opts`; the runtime re-reads them with the same regexes. Lines outside views run at start; picking a view runs its `set` lines and sliders, and its button stays lit while its `set` values hold. Moving a control redraws only the panels' `.vdyn` parts and the captions (`redrawFig`), so focus stays put; a view change rebuilds the figure. Plots are SVG sized to the column, curves are sampled 520 times, and a jump bigger than a quarter of the y range is bisected and drawn straight. Axis labels, legends and captions are HTML, so their math goes through KaTeX; labels inside the SVG are plain text.
- **Hub:** `renderFormulas` (the Formula sheet) shows each formula once per class (the same body in two files is one card, keyed on the body without spaces) with a line per file it's in and the problems that use it (`usedInMap`). `searchIndex(f)` makes one entry per block with where it is ("P2 · (b) · Step 3"); a hit opens the file with `openFile(id, line, reveal)`, and `goLine(n, flash, reveal)` shows the steps up to a hidden one.
- **Standalone copies** (`standaloneHtml`, `standalone`, `readBundle`): `index.html` with a `<script id="tfBundle" type="application/json">` (the files) and a `<script id="tfKatex">` (KaTeX) added right after `<body>`. At startup `readBundle()` adds the files this browser lacks (or has older) and, the first time (`trainFrame:bundleSeen`), opens the file or class. The code writes those tags in two pieces (`"scr" + "ipt"`) so the page's own source never holds them. Notes aren't included.
- **Calculator** (`CALC`, `calcRun`, `buildCalc`; state in `trainFrame:calc`): runs on the frame engine through two hooks in `ev()` that the frame language doesn't use: `env.F` (extra or replaced functions: trig in the chosen angle unit, `log`, `root`, `nCr`, `nPr`, `polar`...) and `env.S` (special forms that take an expression: `deriv`, `solve`). `calcPre()` turns what's typed into engine syntax (× ÷ − π √, `1_3/4`, `5!`, `5 nCr 2`, `5∠30`, `)(`). Results are floats; **F◂▸D** shows an exact form found afterwards (`exactText`: a fraction by continued fractions, a multiple of π, or a root). Tabs: Calc (keypad `KEYS`, history, memory), Solve (`polyRoots`, `linSolve`, `nsolve`), Stats (`stats1`, `regress`), Table, Matrix (`matOp`, `rref`) and Base-n (`baseOp`). Every field has a `data-f` key kept in `CALC.f`. The Calc tab typesets what's typed (`drawPrev`), the history and the answer through KaTeX: `toTex()` turns the engine's syntax tree into LaTeX and `answerTex()` an answer's text; `#calcRes` keeps the plain text in `data-text`. On a touch screen the entry has `inputmode="none"` so the keys type without the phone's keyboard (`abc` in the row above the keys brings it back; that row also moves the caret and steps through the history). At 560 px and under the window is a sheet across the bottom with 46 px keys.
- **Safety:** a frame file is never run as code. Everything from a file goes through `esc()`, and the expression engine (step 3) must be a parser, never `eval` or `Function`.
